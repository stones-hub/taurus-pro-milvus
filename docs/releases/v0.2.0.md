# v0.2.0：可靠性与生产准入整改

## 修复与增强

- Search正确传递向量字段、距离类型及ANN搜索参数，支持多向量字段选择；本地拒绝NaN/Inf等非有限参数。
- 修正AlterAlias调用底层SDK的参数顺序。
- 修复SDK握手失败后遗留gRPC连接的问题，覆盖错误认证、数据库不存在及握手超时。
- 同名并发MustGet共享创建结果；连接建立移出池全局锁，失败连接不再拖住其他名称。
- 新增ContextPool和默认10秒有界创建；支持调用方取消及创建/移除/关闭竞争清理。
- 客户端采用可取消FIFO读写门禁，请求deadline覆盖内部排队；保留数据库切换互斥和SDK安全关闭。
- 修复切库失败后的状态回滚，兼容URL初始库名及显式库优先。
- 集成测试改为环境配置并显式启用；失败不再以跳过掩盖，补齐资源清理和确定性并发回归。

## 升级注意事项

- 最低Go版本仍为1.27.3，Milvus SDK仍为v2.6.5，本次未改go.mod/go.sum。
- Pool原接口保持不变；需要取消创建时使用NewContextPool及AddContext/MustGetContext。
- **连接池Close为终态**：关闭后不能再Add/MustGet复用，需创建新池。
- 等待客户端门禁取消返回context错误；已发RPC沿用SDK/gRPC错误，通过status.Code判断对应状态。
- Close无context参数，等待在途操作结束；裸GetClient需要调用方协调Close/UseDatabase。
- 当前SDK不应用WithRetry配置；生产请求应设置deadline。私有CA依靠运行环境信任库；公共选项不提供mTLS配置。

## 验收

- 最终候选真实Milvus2.6.5全量集成及race各157条测试通过，0失败、0测试跳过；vet通过。
- 原500ms锁等待超时场景约501–502ms返回；URL数据库回滚、Await取消及释放通过。
- 原客户端正常重启和kill/start恢复约14.4秒、15.8秒，Flush后探针数据及搜索正确。
- 最终候选305秒混合负载23271请求，正常错误0、预算超限0。
- 较早阶段另完成真实认证/单向TLS、30分钟混合运行；不将其冒充最终候选完整重跑。

上述为明确版本和本机隔离环境的验收，不外推任意生产容量、HA/mTLS或数天级稳定性。详情见docs/client-deadline-acceptance.md及离线专项报告。
